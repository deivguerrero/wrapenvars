# Delta Spec: Modernize Project to Python 3.12 & uv

## ADDED Requirements

### REQ-01: PEP 621 Build System

The project MUST build with uv using a PEP 621-compliant `pyproject.toml`. The `[build-system]` section MUST declare `hatchling` as the build backend. The `[tool.poetry]` block MUST be removed and replaced with `[project]` containing name, version, description, authors, license, readme, homepage, repository, and `requires-python`.

#### Scenario: uv build succeeds

- GIVEN a `pyproject.toml` with `[project]` and `[build-system]` using hatchling
- WHEN `uv build` is executed
- THEN a valid `.whl` and `.tar.gz` are produced in `dist/`

#### Scenario: Poetry config fully removed

- GIVEN the rewritten `pyproject.toml`
- WHEN inspecting the file
- THEN no `[tool.poetry]` section exists
- AND `poetry.lock` is deleted from version control

---

### REQ-02: Python Version Constraint

The package MUST declare `requires-python = ">=3.12.13,<3.14"` in the `[project]` section.

#### Scenario: uv lock respects version bound

- GIVEN `requires-python = ">=3.12.13,<3.14"` in `pyproject.toml`
- WHEN `uv lock` is executed with Python 3.12.13+
- THEN lock resolution succeeds
- AND no Python 3.14+ or pre-3.12 packages resolve

#### Scenario: Pre-3.12 Python rejected

- GIVEN the version constraint as specified
- WHEN attempting `uv lock` with Python 3.11
- THEN uv reports an incompatible Python version error

---

### REQ-03: Dependency Management via uv

Runtime dependencies MUST remain zero. Dev dependencies MUST include `ruff`, `mypy`, `pre-commit` only — `black` and `flake8` MUST NOT appear. Dependencies MUST be managed via `uv.lock` (generated by `uv lock`).

#### Scenario: Zero runtime deps

- GIVEN the `pyproject.toml` `[project]` section
- WHEN `uv lock` completes
- THEN `uv tree` shows no runtime dependencies

#### Scenario: Dev deps are correct

- GIVEN the `pyproject.toml` `[dependency-groups]` dev section
- WHEN inspecting dev dependencies
- THEN `ruff`, `mypy`, `pre-commit` are present
- AND `black` and `flake8` are absent

#### Scenario: uv.lock replaces poetry.lock

- GIVEN the repo after migration
- WHEN checking versioned files
- THEN `uv.lock` exists
- AND `poetry.lock` does not exist

---

### REQ-04: Code Modernization

`wrapenvars/__init__.py` MUST use modern Python 3.12 idioms: `import json` and `import base64` (no `from X import Y as Z` aliases), precise type hints (`str`, `dict[str, Any]` on `set_dict`), explicit exception types (no bare `except Exception: pass`), and default UTF-8 encoding (no explicit `"utf8"` argument).

#### Scenario: Imports are direct

- GIVEN `wrapenvars/__init__.py`
- WHEN inspecting imports
- THEN `import json` and `import base64` appear at module level
- AND no `from json import loads as jloads` style aliases exist

#### Scenario: Type hints are precise

- GIVEN `wrapenvars/__init__.py`
- WHEN running `mypy --strict wrapenvars`
- THEN zero errors reported
- AND `set_dict` signature uses `dict[str, Any]` for its parameter

#### Scenario: Exception handling is explicit

- GIVEN `wrapenvars/__init__.py`
- WHEN inspecting try/except blocks
- THEN every `except` clause names a specific exception type (e.g., `except (UnicodeDecodeError, ValueError)`)
- AND no bare `except Exception: pass` patterns exist

#### Scenario: UTF-8 encoding is default

- GIVEN `str.encode()` and `bytes.decode()` calls in the module
- WHEN inspecting those calls
- THEN no explicit `"utf8"` or `"utf-8"` string argument is passed (Python 3.12 default)

---

### REQ-05: Pre-commit Hooks

`.pre-commit-config.yaml` MUST include `ruff` (lint + format), `mypy`, and `pre-commit-hooks` (check-merge-conflict, end-of-file-fixer, check-yaml, check-toml, check-json). `black` and `flake8` hooks MUST NOT be present. `pre-commit run --all-files` MUST pass clean.

#### Scenario: Correct hooks present

- GIVEN `.pre-commit-config.yaml`
- WHEN inspecting the hook list
- THEN `ruff`, `ruff-format`, and `mypy` hooks are defined
- AND `pre-commit-hooks` repo includes check-merge-conflict, end-of-file-fixer, check-yaml, check-toml, check-json
- AND no `black` or `flake8` hooks exist

#### Scenario: All hooks pass

- GIVEN the repository in its final state
- WHEN `pre-commit run --all-files` is executed
- THEN all hooks pass with zero errors

---

### REQ-06: PyPI Publishing

The package MUST be publishable via `uv publish`. The `pyproject.toml` MUST include the required metadata (name, version, description, authors, license, repository URL).

#### Scenario: Dry-run publish succeeds

- GIVEN a successfully built package (`uv build` completed)
- WHEN `uv publish --dry-run` is executed
- THEN uv validates the package is publishable
- AND no metadata or structural errors are reported
